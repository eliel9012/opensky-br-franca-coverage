# ADS-B Coverage Report — Era A (fixed window 2026-04-13 → 2026-05-14)

Sensor `-1408044782` (OpenSky volunteer feeder), Franca/SP, Brazil.
Stack: `docker-adsb-ultrafeeder` in k3s. Data source: local `trace_full_*.json`
(gzip-compressed despite the `.json` extension) under `globe_history`.

This window ends **2026-05-14 23:59:59Z**, two days before the antenna swap
(2026-05-16 21:35Z). It is therefore **pure old-antenna (Era A) data**.

## 2. Number of days — counting method (off-by-one)

- **Calendar days, inclusive: 32 days.** Both endpoints counted:
  `(date(2026-05-14) − date(2026-04-13)).days + 1 = 31 + 1 = 32`.
  April 13–30 = 18 days, May 1–14 = 14 days, total = 32.
- This **differs from the existing v3 figure, which said "31 days."** v3 did not
  use a fixed window; it computed `round((last_point − first_point) / 86400)` over
  observed timestamps (`2026-04-13T10:45Z → 2026-05-14T14:23Z ≈ 31.15 d → 31`).
  That is a *rounded duration of the observed span*, not a calendar-day count.
- **Honest figure for this fixed window = 32 days.** The figure, caption and this
  report all use 32. The old "31 days" text should be corrected to 32 (or
  qualified as "≈31-day observed span" if duration is meant rather than calendar
  days).

Note: the window's first calendar day (Apr 13) is partial — the first observed
position is at 10:45Z (see §7). The 32 count is calendar days spanned, not
24h-complete days.

## 7. Gaps / downtime within the window

Method: bucket all kept ADS-B positions into UTC hour bins; flag hours with zero
positions; group consecutive empty hours.

- **One empty interval: `2026-04-13T00:00:00Z → 2026-04-13T10:00:00Z` (10 h).**
  This is **not a mid-window outage** — it is the leading edge of day 1. The fixed
  window opens at midnight, but the first observed ADS-B position is at
  `10:45:15Z`. Hours 00:00–09:59 simply precede the first record.
- **No other empty hours.** From the first observed position (Apr 13 10:45Z) to
  the window end (May 14 23:59:59Z), every UTC hour contains ADS-B positions:
  continuous coverage, no detected downtime.
- Caveat: "no empty hour" means at least one position per hour; it does not prove
  100% uptime at sub-hour resolution. It does rule out any multi-hour outage.

## 8. Feeder uptime ("seconds online") — OMITTED

A feeder "seconds online" metric is **deliberately omitted**. It cannot be
measured exactly and verifiably for *this specific fixed window* from the trace
data alone. The old text carried a value (195342 s ≈ 2.3 days) that contradicted a
31-day window and is not reproducible here. Rather than report an unverifiable
number, it is omitted. The position-level continuity in §7 is the defensible
uptime evidence for this window.

**Cause of divergence:** the v3 figure was generated mid-day on 2026-05-14 and its
last observed point was `14:23:56Z`; it had no date filter and simply processed
whatever traces existed at run time. This rebuild uses the **full fixed window
through 2026-05-14 23:59:59Z**, so it includes the rest of May 14 (≈9.6 more hours
of traffic) plus the now-complete May 14 trace files. That accounts for the extra
positions, aircraft, and files. Range distribution is essentially unchanged
(same antenna, same geometry), which is the expected consistency check.
